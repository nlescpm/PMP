\section{RSD project pages}
\label{app:rsd-page}

Each project at the eScience Center has an 
\href{https://research-software-directory.org/organisations/netherlands-escience-center?tab=projects}{RSD page}. 

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\paragraph{Project Initiation} At the project start, the following data should be added to the RSD project page:
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{itemize}
   \item Grant ID: currently, the Awarding letter reference, for External funders (e.g., EU, NWO) often provide their 
   own ID.
   \item Funder(s): list of all funding organizations, including the eScience Center.
   \item Dates: project start and end dates.
   \item Participating organizations: list of the organizations, including the eScience section(s).
   \item Research domain: relevant project domain, often from the proposal. Multiple domains can be chosen.
   \item Description: typically copied from the proposal abstract.
   \item A cover image: initially a placeholder image provided by the Communication.
   \item Team and maintainers: the Lead RSE and the project team members, including the LAs and their team, 
   with roles and ORCIDs where possible. By default, Lead RSE and SH are listed as a maintainer, while the inclusion of 
   the LA is optional. 
   \item Relevant eInfrastructures used.
   \item Relevant keywords and categories.
   \item eScience funding call name, if applicable.
 \end{itemize}
 During the project lifecycle, the Lead RSE is responsible for managing page updates.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\paragraph{Project Execution} During the project, the following information should be added or updated as needed:
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{itemize}
   \item Repository: URL to the project's GitHub repository (or other version control platform).
   \item Project Team: List of all project team members, including the LAs and their team, with roles and 
   ORCIDs where possible. The Lead RSE should keep this list up to date as team members join or leave the project and 
   use the role field to indicate periods of involvement.
   \item Related Projects: Links to predecessor or related projects in the RSD, where applicable.
   \item Project Outputs: Register project outputs as they become available, including:
   \begin{itemize}
      \item Research outputs: Publications, published datasets, preprints, presentations, posters, reports, 
      websites, notebooks, tutorials, blogs, videos, interviews, news articles, and other dissemination materials. 
      Where available, use persistent identifiers (e.g., publisher DOIs or Zenodo DOIs). Online resources without DOIs 
      may be registered using their URL and a short description.
      \item Research software: Reusable software should have its own RSD software page and be linked to the 
      project. Single-use software (e.g., scripts) may also be archived in Zenodo and referenced using a DOI. Versioned 
      software releases archived in Zenodo can be linked when software has been developed across multiple projects.
      \item Project documentation: Design documents such as the Technology Plan, SMP, and DMP may be published 
      on Zenodo and referenced using their DOIs.
   \end{itemize}
\end{itemize}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\paragraph{Project Closing}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
Before the project is closed, the Lead RSE should review the RSD project page to ensure that it provides a complete
and accurate public record of the project. In particular, verify that:
\begin{itemize}
   \item Project Description: The project description accurately reflects the final project outcomes.
   \item Cover Image: The placeholder image has been replaced by an appropriate project image, where available.
   \item Project Outputs: Publications, datasets, software, and other significant outputs have been registered and 
   linked.
   \item Related Software: Relevant RSD software pages are linked to the project.
   \item Digital Infrastructure: The digital infrastructure used during the project has been documented.
   \item Funding Information: Funding call information and project metadata are complete and up to date.
   \item Project Team: The final project team and maintainers are correctly listed. The Lead Applicant may also be 
   added as a maintainer and contact person to enable future updates to the project page after the project has ended.
   \item Testimonials: Testimonials from project partners or the user community have been added, where available.
\end{itemize}
